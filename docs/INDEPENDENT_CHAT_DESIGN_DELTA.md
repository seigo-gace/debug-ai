# Independent Chat — initial local conversation slice
Source reuse: Astera App `src/features/composer/native-composer.css` blob 5caa3985e569bcc65e08f8212d2c8be0101206a7, browser turn layout and composer controls. The original UI stylesheet is retained; DOM adaptation removes Astera job, credit and account dependencies. Conversation history reuses its turn-ID/idempotency pattern, not its D1 database or billing service. DebugAI's existing Node server and AI Core adapter queue are reused. No second coordinator, model, workflow or KB.
Opt-in: DEBUG_AI_CHAT_ENABLED=true; existing candidate gate configuration DEBUG_AI_COMMAND_MODEL_GATES with qwen35; dedicated chat access credential supplied through existing protected runtime provisioning (never AI Core key in browser). Existing loopback binding preserved. Use an authorized private access path only; do not publish the port or create a tunnel automatically. UI /chat. Token is held in browser memory, not persisted. Single-owner local history in runtime/chat, 0700 directory, atomic 0600 files. No automatic KB ingestion or external dispatch.
Initial delivery: buffered real Qwen conversation, multi-turn context with conservative byte-derived admission, history search/read/delete, text attachment, copy/edit-resend, cancellation request, explicit partial/failure status. No model execution or tool mutations from plain chat. Remaining: authenticated remote browser path, real runtime qualification, streaming, richer history lifecycle, exact tokenizer admission, DeepSeek ordinary chat rights/price/transport, cooperative mode, durable development run binding, KB opt-in/verified learning, distilled-model identity and version switch.
